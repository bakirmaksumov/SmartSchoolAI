# E2E-тесты SmartSchoolAI

Набор Playwright проверяет вход и базовый доступ для ролей `Teacher`, `Student`
и `Admin`, а также полный основной сценарий класса и задания. Тесты запускают
приложение на `http://127.0.0.1:5197` и используют только отдельную SQLite-базу
`E2E/.e2e-data/smartschool-e2e.db`.

## Требования

- .NET SDK 8
- Node.js и npm
- Браузер Chromium для Playwright

## Первый запуск

В терминале перейдите в папку `E2E` и выполните:

```powershell
npm.cmd install
npx.cmd playwright install chromium
npm.cmd test
```

Для показа браузера используйте `npm.cmd run test:headed`. Для проверки типов
TypeScript выполните `npm.cmd run typecheck`.

## Изоляция тестовых данных

Перед каждым прогоном `scripts/run-e2e.mjs`:

1. проверяет и очищает только фиксированные файлы E2E-базы;
2. генерирует случайные пароли в памяти процесса;
3. запускает `Seed`, который повторно проверяет расположение и имя базы;
4. создаёт три синтетические учётные записи;
5. запускает приложение с переопределённым `ConnectionStrings__Default`;
6. удаляет файл базы и SQLite WAL-файлы после завершения тестов.

Тестовые учётные записи: `e2e.teacher@example.test`, `e2e.student@example.test`
и `e2e.admin@example.test`. Пароли генерируются заново при каждом запуске, не
выводятся в лог и не сохраняются в репозитории. Миграции приложения применяются
только к свежей временной E2E-базе. Обычная `smartschool.db` не используется.

Локальный HTTP-сервер работает в окружении `Development`, чтобы не включать
production-перенаправление на HTTPS. Строка подключения и настройки reCAPTCHA
и OpenRouter переопределяются только для процесса E2E; тесты не обращаются к
этим внешним сервисам.

## Покрытие

- Успешный вход студента и преподавателя, открытие их панелей проверяются в
  сквозном сценарии.
- Доступ администратора к панели Admin.
- Перенаправление студента при попытке открыть панель Admin.
- Сквозной сценарий: преподаватель создаёт класс, студент вступает по коду,
  преподаватель создаёт задание с вопросом и назначает его классу, студент
  отправляет правильный ответ, а преподаватель видит результат.
- `auth.spec.ts`: вход/ошибки, редиректы, роли и доступ, регистрация учителя и студента по коду.
- `assignment-flow.spec.ts`: задание из 10 вопросов (текст, один/несколько вариантов), студент отвечает, проверка 70% и 100%.
- `lifecycle.spec.ts`: класс, черновик, дубль/удаление вопроса, предпросмотр, публикация, прохождение, CSV, просмотр ответа, сброс и пересдача, аналитика, закрытие/открытие/удаление.
- `classes.spec.ts`: редактирование, архив/восстановление, ростер студентов, правка и сброс пароля студента, удаление, сброс пароля учителя админом, изоляция чужого класса.
- `misc.spec.ts`: библиотека вопросов (создание/поиск/правка/удаление), профиль, рендер всех страниц, валидация класса.
- Проверка ответа выполняется по ключу ответа и не требует внешнего AI-сервиса.

## Тесты отображения (AI-тьютор и «Solve with photo»)

`tests/tutor-ocr-display.spec.ts` (проект `display`) проверяет, как показываются ответы тьютора и
распознанные шаги. Ответы модели задаёт `scripts/mock-ai.mjs`: приложение получает `OpenRouter__BaseUrl`
на этот мок и проходит весь обычный путь (контроллер, сервис, SSE/JSON, отрисовка в браузере). Тесты
не зависят от `E2E_AI` и от живого провайдера, а свои учётные записи регистрируют через интерфейс.

- `npm test -- --project=display` — запускает приложение (порт 5198), мок (порт 5199) и эти тесты.
- `E2E_BASE_URL=http://127.0.0.1:8080 npx playwright test --project=display` — те же сценарии против
  уже запущенного контейнера (так они выполняются в GitHub Actions); `E2E_MOCK_AI_HOST=0.0.0.0`
  нужен, чтобы контейнер видел мок.
- `E2E_SHOT_DIR=<папка>` сохраняет скриншоты сценариев.
